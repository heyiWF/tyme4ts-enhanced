GETTING STARTED

1. 安装与初始化

本文针对当前仓库版本 。多数查询从一个 DayAlmanac 开始；只做历法转换时，也可直接创建 SolarDay。以下字段示例固定使用 2025-04-03，不随黄历页日期变化；特殊年度接口在代码中明确写出年份。

npm install tyme4ts-enhanced

仓库的新版本尚未发布 npm 时，注册表不包含新增接口。使用仓库源码执行 npm ci、npm run build、npm pack，再在你的项目中安装生成的本地 tgz；不要把包版本不同误判为方法不存在。

TypeScript / ESM
import {DayAlmanac, SolarDay} from 'tyme4ts-enhanced';

const a = DayAlmanac.fromYmd(2025, 4, 3);
const solar = SolarDay.fromYmd(2025, 4, 3);
const sameDay = DayAlmanac.fromSolarDay(solar);

console.log(a.getLunarDay().toString()); // 农历乙巳年三月初六
console.log(sameDay.getDuty().getName()); // 闭

CommonJS 可用 const {DayAlmanac} = require('tyme4ts-enhanced')。浏览器需使用 type="module" 并导入构建后的 ESM 文件；本 Wiki 使用同目录 ./tyme.mjs，浏览器不会自动解析 npm 裸包名。

2. 对象与字段取值

getLunarDay() 返回农历日对象，而非字符串。对象适合继续计算；展示时再取名称或完整描述。不要解析中文日期字符串来提取年月日。

需要什么如何读取结果类型
公历年月日a.getSolarDay().getYear() / getMonth() / getDay()number
农历日期对象a.getLunarDay()LunarDay
农历完整描述a.getLunarDay().toString()string
日干支名称a.getSixtyCycleDay().getSixtyCycle().getName()string
宜事项名称列表a.getSixtyCycleDay().getRecommends().map(x => x.getName())string[]

getName() 通常只返回名称，toString() 返回完整描述；具体以每个字段的输出为准。数组用 map 提取成员属性，布尔值直接用于条件判断。公共接口不保证所有对象都具有相同方法，以下条目已分别给出可用调用链。

组装你的页面数据
import {DayAlmanac} from 'tyme4ts-enhanced';

const a = DayAlmanac.fromYmd(2025, 4, 3);
const solar = a.getSolarDay();
const lunar = a.getLunarDay();
const data = {
  year: solar.getYear(), month: solar.getMonth(), day: solar.getDay(),
  lunar: lunar.toString(),
  leapMonth: lunar.getLunarMonth().isLeap(),
  duty: a.getDuty().getName(),
  recommends: a.getSixtyCycleDay().getRecommends().map(x => x.getName()),
  deity: a.getDeityFestival()?.getName() ?? null,
  festivals: a.getFestivals().getEntries().map(e => ({
    name: e.getName(), category: e.getCategory(), source: e.getSource()
  }))
};
console.log(JSON.stringify(data, null, 2));

3. 参数、空值与日期边界

  • 年月日：月为 1–12，日从 1 开始；JavaScript Date.getMonth() 要加 1。用明确年月日创建对象，可避免解析 UTC 日期字符串导致的本地日期偏移。DayAlmanac.fromDate(date) 读取运行环境的本地年月日。
  • 闰月：LunarDay.fromYmd(2023, -2, 1) 表示闰二月初一。月对象的 getMonth() 取绝对月号，getMonthWithLeap() 保留负号，isLeap() 单独判断闰月。
  • 索引：星期索引 0 为周日，1–6 为周一至周六；节气日索引 0 是交节当日。要展示“第几天”需加 1，不要对所有数字统一加 1。
  • 时刻：日级对象不包含出生时分秒。八字使用 SolarTime.fromYmdHms(...).getSixtyCycleHour().getEightChar()；农历年、日级干支年与立春时刻的年柱口径不同。
  • 空值：神诞、年号、当日假期可能为 null，数组可能为空。使用可选链、判空或检查数组长度；不要直接使用非空断言掩盖真实缺失。
  • 数据范围：各国家历法有不同表范围；超范围先检查说明并捕获异常。日期推算不等于完整官方公告。HKO 2057 年已知差异见核验报告。

4. 节日、放假与活动：选择对应接口

需求入口关键约定
当天有哪些传统节日、纪念日a.getFestivals().getEntries()读取名称、分类、来源；不自动代表放假
严格读取已核验年度安排OfficialHolidayCalendar.create(region, year)缺少年度报错；getScope() 明确适用对象
规则推算、自定义导入HolidayCalendar.create(region)独立实例；of(region) 是共享可变实例
公共活动跨多天或一个月FestivalPeriods.getYear(year)起止日期均包含；未公布的阅读周年份不推算

完整年度导入使用 mode: 'replace'，停用该年度规则及自动补假；增补使用默认 merge。字段必须包括准确的地区、年度与日期。接口不能把另一地区的完整年度表替换进来。

例如台湾 2025 年表中的 118 日是机关休息日总数，包含周末；getDays(true) 另含补班。美国表采用 OPM 常规联邦雇员工作安排。需同时读取 getScope() 和 getSource()，不能只保留一个假期名称。

8 类来源

这一天是第几个节日？

例如，2026 年 11 月 9 日是第 35 个全国消防日。序号从首个适用的节日日期起算，首届为 1；它与历史事件的周年、人物年龄、节日持续的第几天分别计算。

世界统计日自 2010 年起每五年一次，2025 年是第 4 次，2026 年不列此节日。日本祝日改期或改名延续原序列，2019 年缺席的天皇诞生日不计入。新西兰 Matariki 仅按法律列明的逐年日期计数。

「未核定」表示缺少可靠起点或连续性依据，保留原名，不按公历年份猜测。补假、调休上班及连休的其他日期不重复计数。公共假日的次数不等于传统本身的年龄；未来序号是现行制度不变时的推算。

import {Festivals, FestivalOrdinals, SolarDay} from 'tyme4ts-enhanced';
const day = SolarDay.fromYmd(2026, 11, 9);
const fire = Festivals.of(day).getEntries().find(e => e.getName() === '全国消防日');
console.log(fire?.getOrdinal());     // 35
console.log(fire?.getOrdinalName()); // 第35个全国消防日
console.log(fire?.getOrdinalInfo()); // 计数范围、核验日期与来源
console.log(Festivals.of(day).getNames(true));
console.log(FestivalOrdinals.get('世界统计日', SolarDay.fromYmd(2026, 10, 20))); // null

国家与地区页的假日也提供相同的 getOrdinal()、getOrdinalName() 和 getOrdinalInfo() 接口。原有 getName()、toString() 保持兼容。完整核验报告与接口边界 ↗
